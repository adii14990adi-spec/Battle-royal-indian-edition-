# Mobile Optimization — Unity 6 URP (Task 3)

Targets: the committed baseline in [../UNISOC_BUDGET.md](../UNISOC_BUDGET.md)
(Unisoc T606 class, Low profile) and the Snapdragon 6s Gen 3 class High
profile in [../performance/ANDROID_PROFILES.md](../performance/ANDROID_PROFILES.md).
The runtime already switches URP render scale, shadow distance/cascades, MSAA
and additional-light limits through `QualityProfile` — this document covers the
content-side rules: LODs, shaders/lighting, and input.

## 1. LOD Groups for trees and modular buildings

### Trees (Forest & Quarry POI)

1. Import the tree FBX/glTF into `Assets/UserAssets/Models/`.
2. Select the root → **Add Component → LOD Group**.
3. Three renderers, authored in Blender (see
   [../asset-pipeline/BLENDER_PIPELINE.md](../asset-pipeline/BLENDER_PIPELINE.md)):
   * **LOD0** — full mesh (< 1 500 tris), within 25 m;
   * **LOD1** — decimated ~50 % (< 700 tris), 25–60 m;
   * **LOD2** — two crossed cards or < 150-tris silhouette, 60–120 m;
   * **Culled** beyond 120 m (matches the Low profile view distance).
4. Set LOD percentages 25 / 60 / 120 (screen-relative ≈ 0.4 / 0.15 / 0.02) and
   press **Recalculate Bounds**.
5. For dense forest scatter use GPU Instancing on the shared material +
   `LODGroup.fadeMode = CrossFade` off on Low (cross-fade costs a full extra
   pass — SpeedTree-style dithering is High-profile only).

### Modular buildings (Military Base, Village)

1. One LOD Group per **prefab**, not per mesh: LOD0 = detailed prefab
   (< 2 500 tris), LOD1 = merged/decimated shell (< 900 tris), LOD2 = boxy
   silhouette (< 200 tris, interiors removed — nobody sees inside at 150 m).
2. Keep colliders on the LOD Group root so physics cost does not scale with
   visual LOD; never put colliders on LOD renderers.
3. Village houses: 15 instances of **one** prefab variant with different
   rotations — Unity's SRP Batcher batches them as long as they share the
   shader and material set.
4. Watch the 50 m detail-disk contract of the Siran terrain
   ([../architecture/UNITY_ARCHITECTURE.md](../architecture/UNITY_ARCHITECTURE.md)):
   buildings stream with their 500 m chunk; give each chunk's content a
   matching LOD budget so a chunk never exceeds ~250 k resident triangles.

**Budgets (per screen):** ≤ 300 k triangles visible, ≤ 150 draw calls for
world content, ≤ 60 FPS frame time 16.6 ms with 4 ms CPU headroom for
streaming. Validate with the in-game `PerformanceMonitor` overlay.

## 2. URP / Shader Graph settings for mobile

The project's URP assets are generated by
**Battle Horizons → Project Setup → Configure** with Low-safe defaults
(renderScale 1.0 → runtime-adjusted, MSAA 1, 2 cascades, 60 m shadow distance,
512 px main-light shadowmap, 2 additional lights). Rules for new content:

* **Shader Graph target**: Universal Render Pipeline / **Lit** for hero props,
  **Simple Lit** for everything else; Unlit for stylised/flat POIs. Never
  target HDRP or Built-in — `validate_csharp.py` fails HDRP dependencies.
* In the graph, **delete unused blocks**: no Clear Coat, no Detail maps, no
  subsurface. One Base Color + Normal + Smoothness input is the house style
  (committed terrain materials are `metallic 0, smoothness 0` matte).
* **Keywords**: prefer static branches over shader features; every
  `#pragma multi_compile` doubles variants and Android build time. Strip
  unused variants in URP asset → Shader Stripping (disable additional-light
  shadows, keep fog).
* **Shadows**: main light only. Additional lights: no shadows on Low, max 4
  lights/High, 2/Low (already enforced by `QualityProfile`). Casters: POI
  buildings cast, small props receive-only, loot pickups neither.
* **Lighting = baked**: Lightmapper → Progressive GPU (or CPU on the build
  machine), **Baked Indirect** at minimum; static geometry flagged
  Contribute GI; lightmap resolution 10–14 texels/m; compress lightmaps to
  ASTC via the platform override. Realtime Global Illumination stays **off** —
  it is the single most expensive mobile feature. One directional light
  (sun) realtime for the day cycle; everything else baked or unlit.
* Textures: ASTC 6×6 for world albedo/normal (already the Android default),
  max 1024² for environment, 512² for props, mipmaps on, no Read/Write.
* The safe-zone wall and loot greybox deliberately use one primitive +
  solid colour — replace the wall with a Scroll-free unlit shader-graph
  cylinder (vertical gradient + rim alpha) when art lands; still one draw call.

## 3. New Input System — movement snippet

The shipping stack already exists:
[`VirtualJoystick`](../../unity-project/Assets/Scripts/Player/VirtualJoystick.cs)
(pointer-event joystick, `Vector2 Value` with a 0.12 dead zone) →
[`PlayerInputRouter`](../../unity-project/Assets/Scripts/Player/PlayerInputRouter.cs)
(merges touch look + keyboard/mouse into `Move`, `LookDelta`, sprint/jump/
crouch/aim flags) →
[`PlayerController`](../../unity-project/Assets/Scripts/Player/PlayerController.cs)
(`CharacterController` movement) +
[`ThirdPersonCameraController`](../../unity-project/Assets/Scripts/Camera/ThirdPersonCameraController.cs)
(`AddLook` yaw/pitch orbit). `activeInputHandler: 1` (new Input System only) is
committed in ProjectSettings and validator-enforced.

Minimal standalone version of the same contract, for new scenes/tests:

```csharp
using UnityEngine;
using UnityEngine.InputSystem;

namespace BattleHorizons.Gameplay.Match
{
    /// <summary>Joystick/WASD movement + right-stick/drag look, camera-relative.</summary>
    [RequireComponent(typeof(CharacterController))]
    public sealed class SimpleMoveAndLook : MonoBehaviour
    {
        [SerializeField] private Transform cameraPivot;   // yaw root of the camera
        [SerializeField] private float walkSpeed = 4.0f;
        [SerializeField] private float lookSensitivity = 0.15f;

        private CharacterController _controller;
        private Vector2 _move;      // from an InputAction "Move" (Vector2, joystick/WASD)
        private Vector2 _look;      // from an InputAction "Look" (Vector2, delta)
        private float _pitch;

        private void Awake() => _controller = GetComponent<CharacterController>();

        // Wire these in an .inputactions asset: Move = <Gamepad>/leftStick + <Keyboard>/wasd,
        // Look = <Gamepad>/rightStick + <Pointer>/delta. Processed by PlayerInput or manually.
        public void OnMove(InputValue value) => _move = value.Get<Vector2>();
        public void OnLook(InputValue value) => _look = value.Get<Vector2>();

        private void Update()
        {
            // Camera-relative movement: forward = camera yaw projected on XZ.
            var yaw = cameraPivot != null ? cameraPivot.eulerAngles.y : 0f;
            var forward = Quaternion.Euler(0f, yaw, 0f) * Vector3.forward;
            var right = Quaternion.Euler(0f, yaw, 0f) * Vector3.right;
            var velocity = (forward * _move.y + right * _move.x) * walkSpeed;

            _controller.Move(velocity * Time.deltaTime);

            if (cameraPivot != null)
            {
                cameraPivot.Rotate(0f, _look.x * lookSensitivity, 0f);
                _pitch = Mathf.Clamp(_pitch - _look.y * lookSensitivity, -70f, 60f);
                // Apply _pitch to the camera's local X rotation here.
            }
        }
    }
}
```

Rules that keep input mobile-cheap: poll actions in `Update` (never
`FindObjectOfType` per frame — validator rule 8), reuse `Vector2` structs, and
route on-screen buttons through `PlayerInputRouter.SetSprintHeld`/`SetAimHeld`
style setters rather than new `PlayerInput` components per button.
