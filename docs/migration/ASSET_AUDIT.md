# Phase 1 — Audit of the Godot project

Date: 2026-11-09
Repository: `adii14990adi-spec/Battle-royal-indian-edition-`
Branch audited: `main` @ `d93598d`

This is the audit that Phase 1 of the migration brief requires: what exists,
what it actually does, what it is missing, and — for each gap — whether the
migration has to fill it or merely report it. Nothing here is aspirational; every
statement is either read from a file in the repository or marked **absent**.

> **Method.** Files were read directly. The 9.2 MB baked scene was decoded with a
> Python parse of the `.tscn` text format (no Godot binary is available in this
> environment), then cross-checked against the summary resource and against a
> second, independent decoder pass. Where the two disagreed, the disagreement is
> recorded below rather than smoothed over.

## 3. What the game actually is today

Read this carefully, because it determines how much of the brief can honestly be
delivered.

**Implemented and runnable in Godot**

1. **Siran Island, fully baked.** A 4 km × 4 km terrain generated by a 7-pass
   heightmap bake, meshed into 64 chunks of 500 m, with physics colliders, vertex
   colouring by zone, a lake, a moat ring, a river and 5 roads. 320,000
   triangles, 166,464 vertices, height range −38.00 … 64.84 m.
2. **Chunk streaming** (`chunk_manager.gd`): radius / keep-ring / throttle model
   that only instantiates chunks near the camera. This is real, tuned code.
3. **Boot → world link** (`boot.tscn`, `boot_screen.gd`, `boot_world_link.gd`):
   a loading screen that loads the island scene and spawns the player on the
   ground at the configured spawn point.
4. **Free-fly debug spectator** over the island with a debug HUD
   (`debug_spectator.gd`, `world_debug_hud.gd`).
5. **Perf manager autoload** (`perf_manager.gd`): frame-time sampling and
   adaptive quality nudge.
6. **Save manager** and **audio manager** autoloads (skeletons: keys and buses,
   no content).
7. **Self-check scene** (`phase3_selfcheck.tscn` + `verify_phase3.sh`): proves the
   bake is internally consistent (triangle counts, winding, collider agreement).
8. **CI**: Godot 4.4.1 + Android SDK 34 + JDK 17, runs the phase gates, exports a
   release APK, enforces a 120 MB size limit, publishes on `v*` tags.

**Absent — not stubs, absent**

These are requested by the migration brief but **do not exist in the source
project**. The audit found `.gitkeep`-only folders and no code referencing them.
They are listed so the report can distinguish "migrated" from "never existed":

| Expected by the brief | Reality in the Godot project |
| --- | --- |
| Third-person player | none — only `scripts/player/.gitkeep` |
| Camera rig with collision | none |
| Jump / crouch / aim / reload | none |
| Touch controls (joystick, buttons) | none |
| Characters, rigs, animations | `assets/models/*` are all `.gitkeep`; `scenes/characters/.gitkeep` |
| Weapons, loot, inventory | `resources/loot_tables/.gitkeep`, `scenes/weapons/.gitkeep`, `scenes/loot/.gitkeep` |
| Vehicles | none |
| Bots / AI | none (`scripts/systems/.gitkeep`) |
| Buildings, props, vegetation | none — the project's own `README.md` says so |
| **The modern mansion at 56.1% X / 31.1% Y** | **no coordinate, no mesh, no scene node anywhere in the repository** |
| Audio assets | `assets/audio/**` `.gitkeep` only |
| Fonts | `assets/fonts/.gitkeep` |

Two consequences the migration must not paper over:

* **"Character integration" cannot be a port.** There is nothing to port. Phase 4
  is therefore *pipeline + a verified rig harness*, and the report says so.
* **The mansion is a design requirement with no implementation.** The conversion
  preserves the *map* faithfully (zones, roads, water, terrain) but a building at
  a stated map coordinate does not exist on either side yet. Inventing one would
  be fabricating an asset, so it is reported as a gap with the coordinate
  preserved for whoever builds it.

## 4. The baked map — what the port must reproduce exactly

This is the part of the project with real engineering value and the part the
migration must not lose.

### Design layout (`scripts/world/siran_map_config.gd`, `generator_version = 3`)

| Parameter | Value |
| --- | --- |
| Sea level | `0.0` |
| Island radius | `1950 m`, coastline noise `±170 m` |
| Height range | `min -38 m`, `max 132 m` |
| Noise seed | `20261106` |
| Spawn point | `(40, 28, -30)` |
| Grid | `401 × 401` samples, **10 m** spacing, `half_extent = 2000` |
| Lake | centre `(250, -1150)`, radii `(520, 380)`, surface `9.0 m` |
| Moat | radii `(490, 430)`, rotated −12° |
| River | 9 control points `(250,-790) → (1200,2060)`, width `70 → 110 m`, surface `9.0 → −0.5 m` |
| Roads | 5, width `16 m`, shoulder `7 m` |

### Zones (all preserved verbatim in the C# port)

| Zone id | Kind | Centre (x, z) | Size (m) | Rotation | Flat height |
| --- | --- | --- | --- | --- | --- |
| `factory_island` | INDUSTRIAL | (−1250, −1300) | 760 × 640 | −12° | 26 m |
| `konkan_docks` | DOCK | (−1470, 130) | 780 × 540 | 6° | 4.5 m |
| `central_state` | URBAN | (40, −30) | 1150 × 1150 | 0° (rounded rect) | 16 m |
| `graveyard_center` | GRAVEYARD | (1350, −80) | 820 × 900 | 12° | 42 m |
| `aircraft_industry` | AIRFIELD | (120, 1480) | 1020 × 740 | 0° (rounded rect) | 12 m |

`corner_radius_m = min(width, depth) × 0.22` for rounded-rect zones. The brief's
zone list (industrial NW, city centre, foggy graveyard E, military runway S,
coastal dock SW, river through the middle) maps 1:1 onto this table — which is how
the port was verified: by checking each brief element against a real row.

### Bake output (measured, not assumed)

| Measurement | Value |
| --- | --- |
| Surfaces in `siran_island_baked.tscn` | 82 (64 chunk + 18 road ribbons) |
| Chunk size | 500 m, 5,000 tris each |
| Height-map colliders | 64 × `HeightMapShape3D`, 51 × 51 samples |
| Vertices / triangles | 166,464 / 320,000 |
| Mesh-vs-collider agreement | within 1e-3 m (asserted by `verify_phase3.sh`) |
| Winding | clockwise, Y-up — **same as Unity**, so no index flip |
| `array_mesh` wire layout | `aabb`, `attribute_data`, `format`, `index_count`, `index_data`, `primitive`, `uv_scale`, `vertex_count`, `vertex_data` |
| Vertex stride | 20 B interleaved (position 12 B, packed normal+tangent 8 B); positions must be sliced before decoding |
| Colours | RGBA8 per vertex, zone palette |
| Terrain normals | **garbage in the bake** — must be rebuilt from the height field |
| River surface | `.res` binary `RSRC`, not text — must be rebuilt from config |

The last three rows are the traps: a naive importer produces a correctly-shaped
island with black lighting and an invisible river. The Unity conversion rebuilds
normals from heights and regenerates the river ribbon from the control points.

## 5. Performance budget already agreed by the project

`docs/UNISOC_BUDGET.md` and `perf_manager.gd` encode a hard budget. The Unity
port inherits it as the **Low** profile and adds a **High** profile on top:

| Budget | Low (Unisoc T606 floor) | High (8 GB class) |
| --- | --- | --- |
| Device PSS | ≤ 800 MB | ≤ 1,400 MB |
| GPU memory | ≤ 180 MB | ≤ 400 MB |
| Draw calls | ≤ 60 | ≤ 150 |
| Frame time | ≤ 33.3 ms | ≤ 16.6 ms |
| Bots | 25 | 40 |
| Texture size | ≤ 512² | ≤ 1024² |
| Physics tick | 30 Hz | 30 Hz |
| Lights per object | ≤ 2 | ≤ 4 |
| Post-processing | none | selective |

No FPS number is claimed anywhere in this migration before hardware testing; the
budgets are budgets, and `docs/migration/REPORT.md` records that they are
unverified on hardware.

## 6. CI and release process (existing, must survive)

`.github/workflows/build.yml`:

```
gates  → verify_phase1.sh + verify_phase3.sh + check_project_config.gd + check_baked_scene.gd
build  → Godot 4.4.1, Android SDK 34, JDK 17, --export-release, APK_SIZE_LIMIT_MB=120
publish→ on v* tags, attaches the APK to a GitHub release
```

`.github/actions/setup-godot-android/action.yml` is a composite action that
installs Godot and the Android SDK. Both are **untouched** by this migration; the
Unity port gets a second, independent workflow (`.github/workflows/unity.yml`).

## 7. Code quality findings that affect the port

| Finding | Consequence for Unity |
| --- | --- |
| `island_shape_math.gd` is pure maths (no engine calls) | ported line-for-line to `IslandShapeMath.cs`, then unit-tested |
| `siran_map_config.gd` is pure data | machine-ported to `SiranMapConfig.cs` by `port_siran_config.py`, with a CI drift gate |
| Bake scripts are editor-only and CPU-bound | not ported; the *output* is consumed instead. Re-baking stays a Godot job |
| `chunk_manager.gd` couples streaming to node lifetime | re-implemented as `SiranChunkStreamer` with an explicit pool |
| Autoloads (`PerfManager`, `SaveManager`, `AudioManager`) are singletons | `PerformanceMonitor` + `GameBootstrap`; save/audio deferred (nothing to save/play yet) |
| Custom `gdshader` greybox shaders (unshaded) | URP Lit + vertex-colour keyword, or unlit-teal water |
| No `CharacterBody3D` anywhere | the third-person controller in Unity is **new code**, documented as such |

## 8. Phase 1 conclusion

The source project is a **world-generation and baking project with a working
Android build pipeline**, not a gameplay project. Its valuable, hard-won content
is the island (data + bake + streaming + verification). The migration therefore:

1. ports the island faithfully and *provably* (byte-level checks against the
   bake, not "looks the same"),
2. rebuilds the missing gameplay foundation in Unity as new, tested C#,
3. reports the absent gameplay/art content as absent rather than improvising it,
4. keeps the Godot project as the reference implementation and fallback target.

Everything downstream of this decision is in `docs/migration/REPORT.md`.
