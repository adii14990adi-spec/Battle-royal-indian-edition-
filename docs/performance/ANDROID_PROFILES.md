# Android graphics profiles and verification status

Two Unity URP quality profiles are configured for Android. These are code and
project settings, not evidence of achieved FPS, memory use or thermal behaviour.

> **No device-performance claim:** the Unity editor/test runner and Android device
> have not been run in this workspace. The GameCI workflow can perform the editor
> checks when `UNITY_LICENSE` is configured; device measurements remain a separate
> acceptance step.

## Settings ownership

| Layer | File | Responsibility |
| --- | --- | --- |
| Quality levels | `unity-project/ProjectSettings/QualitySettings.asset` | Low and High static quality settings |
| URP asset | Generated by `Assets/Editor/ProjectBootstrap.cs` | Forward renderer, render targets, shadows, additional lights |
| Runtime | `Assets/Scripts/Core/QualityProfile.cs` | device selection, profile switch, frame-rate target and URP overrides |
| World visibility | `Assets/Scripts/World/SiranChunkStreamer.cs` and `SiranRadiusClip.shader` | fixed 50 m circular visible radius over the 500 m tile grid |
| Imports | `Assets/Editor/AssetImportRules.cs` | ASTC, mipmaps, texture-size and audio import rules |

The generated URP assets and scenes are produced by **Battle Horizons > Project
Setup > Configure**. The committed URP package version is in
`unity-project/Packages/manifest.json`.

## Low profile

Low is the Android default and the conservative target for entry-level hardware.

| Setting | Value |
| --- | --- |
| Render scale | 0.85 |
| HDR / post-processing | Off / none |
| MSAA | 1× |
| Main-light shadows | 2 cascades, 60 m distance, 512 px map, hard shadows |
| Additional lights | Maximum 2 per object |
| Texture import | ASTC 6×6 on Android; maximum 512 px; mipmaps on |
| Anisotropic filtering | 0 |
| Terrain visibility | full-map Terrain renderer always disabled; visible terrain uses radius-clipped streamed meshes |
| Circular visual radius | **50 m**, fixed; tile source size remains 500 m |
| Frame-rate target | 30 fps cap (not a measured result) |

## High profile

High is intended for devices reporting at least 5.5 GB system memory and 8 CPU
cores, subject to available graphics memory.

| Setting | Value |
| --- | --- |
| Render scale | 1.0 |
| HDR / post-processing | Off / none |
| MSAA | 2× |
| Main-light shadows | 4 cascades, 120 m distance, 1024 px map, hard shadows |
| Additional lights | Maximum 4 per object |
| Texture import | Same 512 px ASTC 6×6 cap as Low |
| Circular visual radius | **50 m**, same as Low |
| Frame-rate target | Up to 60 fps, capped to display refresh (not a measured result) |

`QualityProfiles.StreamRadius()` deliberately returns 50 m for both profiles. A
quality switch cannot silently expand the rendered world beyond the requested
circle. Quality continues to affect render scale, shadows, light limits and frame
pacing.

## Streaming and visible geometry

The map data uses an 8 × 8 grid of 500 m source tiles. The streamer keeps only tile
rectangles intersecting the focus point's 50 m disk (one to four tiles depending
on proximity to tile edges). The custom URP shader clips terrain, roads and water
against the exact world-space circle. The full-map Unity Terrain heightmap is not
rendered over the streamed meshes; its collider remains available across the map.

The tile-membership check runs at 5 Hz and reacts to movement within a tile. The
shader focus is updated each frame. This describes implementation, not a measured
performance result. The project needs an actual Unity render and Android device
check to verify visual seams, shader compatibility and cost.

## Profile selection

```text
High ⇔ systemMemoryMb >= 5500
       && processorCount >= 8
       && (graphicsMemoryMb == 0 || graphicsMemoryMb >= 1500)
Low  otherwise
```

Unknown graphics memory does not veto High. A stored player override takes
precedence over automatic detection. The default Android quality level is Low,
so the first rendered frame starts conservatively.

## Device verification runbook

After a successful Android APK build:

```bash
adb install -r build/battle-horizons.apk
adb logcat -s Unity
adb shell dumpsys meminfo com.aurastudios.battlehorizons | head -30
adb shell dumpsys gfxinfo com.aurastudios.battlehorizons framestats | head -40
```

In the PlayerTest scene, F3 opens the development HUD. It displays cached frame
time, Unity ProfilerRecorder data, managed heap, Unity-reserved memory and
resident chunk count. These are diagnostic values; Unity-reserved memory is not
Android PSS. Record device model, OS version, profile, resolution and test duration
alongside measurements. Run a sustained thermal test before making FPS claims.
